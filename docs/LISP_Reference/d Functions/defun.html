defun

(defun [c:] name ([arg1 arg2 ...] / [local-var1 local-var2 ...]) expression)

Defines a custom LISP routine for ZWCAD.

A LISP file acts as a container for multiple functions, which become accessible within ZWCAD after loading the file via the load command. Each function must be declared individually using defun.

The defun keyword initiates the function definition, followed by the function name and parameter structure. Three declaration approaches are available:

  • Global variables: Empty parentheses indicate all variables retain values after execution. Example:

    (defun demoFunc ( )
    ??(setq val 42)
    )

    Other functions in the file will recognize val as 42.

  • Local variables: Variables declared after a slash (/) reset after function completion. Example:

    (defun demoFunc ( / temp)
    ??(setq temp 24)
    )

    temp will only exist during demoFunc's execution.

  • Input parameters: Variables before the slash receive external values. Example:

    (defun demoFunc (input / result)
    ??(setq result (* input 2))
    )

    Call using (demoFunc 5) to process the argument.

Adding C: before the function name enables command-line execution without parentheses. This integrates your function with native ZWCAD commands like Polyline or Hatch:

(defun C:myCmd ( / settings)
??(initget 1)
??(setq settings (getreal "\nEnter scale factor: "))
)

Implementation Note

The C: prefix denotes a command-line accessible routine, unrelated to drive letters. Ensure all local variables are declared after the slash to prevent unintended value retention between function calls. Expressions within the definition execute sequentially until the final closing parenthesis.

Examples

Code Result
(defun demoFunc ?( )...) demoFunc accepts no input and has no local variable.
(defun demoFunc ?(input / result). . . ) demoFunc accepts one input and has one local variable.
(defun demoFunc ?( / temp). . . ) demoFunc has no input and one local variable.
